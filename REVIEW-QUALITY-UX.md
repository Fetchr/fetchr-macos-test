# Ревью качества и UX — Fetchr v0.3.1 (2026-06-09)

Объём проверки: Rust-бэкенд (src-tauri, ~20k строк), фронтенд (src, ~35k строк), конфигурация, i18n, структура репозитория. Безопасность не рассматривалась (см. отдельный REVIEW.md).

---

## 1. Баги, влияющие на пользователя

### 1.1 Drag&drop файлов не работает (Fetchr Mute)
`src/ui/redesign/fetchr-mute/FetchrMutePage.tsx:291` — `(file as any).path`. В Tauri v2 объект `File` из HTML5-события drop не содержит `path`, поэтому пользователь при перетаскивании **всегда** получает ошибку «Не удалось определить путь к файлу».
Фикс: подписка на `getCurrentWebview().onDragDrop()` из `@tauri-apps/api/webview` — событие отдаёт реальные пути. HTML5-обработчики оставить только для подсветки зоны.

### 1.2 Очередь не переживает перезапуск
`src-tauri/src/jobs/queue.rs` — состояние очереди нигде не сохраняется на диск (нет save/load). Закрыл приложение — потерял все задачи, включая «в ожидании» и «ошибка» с настройками. Для менеджера загрузок это базовое ожидание.
Фикс: сериализовать `Vec<Job>` в JSON в app-data при каждом изменении, при старте восстанавливать (running → queued).

### 1.3 Переключатель языка фактически не работает
В настройках есть смена языка (`GeneralSettingsCard.tsx:35`), но в redesign-UI **832 захардкоженные русские строки в 67 файлах** (`src/ui/redesign/**`). Ключи вида `purevoice.*` отсутствуют в `en.json`/`ru.json` — всегда срабатывает русский fallback. Расхождение словарей: 8 ключей есть в ru и нет в en, 2 — наоборот.
Фикс: либо честно убрать EN из списка до выноса строк в словари, либо вынести строки (механически: t() уже импортирован в 34 файлах).

### 1.4 Неверная версия в легаси-шапке
`src/components/title-bar.tsx:50` — хардкод `v0.2.5` при версии приложения 0.3.1. Также `scripts/visual-version.mjs` патчит версию в исходник регексом — хрупко (ломается при переформатировании JSX).
Фикс: `define: { __APP_VERSION__: JSON.stringify(pkg.version) }` в `vite.config.ts`, удалить скрипт и хардкоды.

### 1.5 Фейковая «анимация сканирования» задерживает результат
`FetchrMutePage.tsx:209` — после фактического завершения обработки UI 8 секунд проигрывает скриптованный «скан» (`scanDurationMs = 8000`) и только потом показывает результат. Это вводит в заблуждение и крадёт время на длинной сессии (каждый рецензор — снова 8 с?).
Фикс: убрать или сократить до ~1 с как transition; прогресс должен отражать реальную работу.

## 2. Обработка ошибок

### 2.1 Ошибки уходят в console.error, пользователь их не видит
14+ мест в `src/ui/redesign/**`: загрузка истории (`FetchrMutePage.tsx:179`), machineId (`:172`), удаление элемента истории и т.п. Если бэкенд-команда упала, страница просто молчит (пустая история без объяснения).
Фикс: единый helper `notifyError(err)` → toast (sonner уже в зависимостях, но нигде не используется) + console.

### 2.2 Молчаливый catch с договорённостью «store сам обработает»
`FetchrMutePage.tsx:320` — `catch (err) { /* error handled in store */ }`. Контракт неявный: если store перестанет ставить error, ошибка исчезнет бесследно. Лучше, чтобы store возвращал результат, а не бросал, либо убрать try/catch вовсе.

### 2.3 Side-effects внутри setState-updater + setTimeout(50)
`FetchrMutePage.tsx`, `importWords`: внутри `update((current) => {...})` вызываются `suggestNewWords` и через `setTimeout(50)` — `triggerRecensor`. Updater должен быть чистым: в StrictMode React вызывает его дважды → двойная отправка слов и двойной рецензор; 50 мс — гонка, а не синхронизация.
Фикс: вычислить `nextVal` снаружи, затем последовательно setState → recensor.

### 2.4 Позиционные булевы параметры IPC
`src/lib/ipc.ts:374-405` — `splitLiveRecording(id, true, false, true, false, …)`: 4-5 булевых флагов подряд, перепутать порядок незаметно для компилятора (все boolean).
Фикс: принимать объект `{ fetchrMuteEnabled, … }` как уже сделано в `trackSponsorZone`.

### 2.5 `fetchBytes` возвращает `number[]`
`ipc.ts:172` + команда `fetch_bytes` — байты сериализуются в JSON-массив чисел: ×5-10 памяти и CPU на больших сегментах.
Фикс: `tauri::ipc::Response` (raw bytes) и `ArrayBuffer` на фронте.

### 2.6 Магические проценты стадий в run_job
`src-tauri/src/jobs/runner.rs:145-155, 299-336` — границы стадий (50/60/70/80/95) разбросаны по if-каскадам в двух местах; при добавлении новой стадии их легко рассинхронизировать (recipe для «прогресс прыгнул назад»).
Фикс: построить план стадий заранее: `Vec<(Stage, f32, f32)>` из одной функции и итерироваться по нему.

### 2.7 Смешение языков в сообщениях бэкенда
`runner.rs:96` «Очистка аудио от матов» рядом с `:162` «Downloading source video» — статусы и логи у пользователя двуязычные.
Фикс: бэкенд шлёт коды стадий (`stage: "fetchr_mute"`), фронт переводит через i18n.

## 3. Структура и дублирование

### 3.1 Три поколения UI живут одновременно
`src/features/*` (legacy) + `src/features/*/legacy-*` + `src/ui/redesign/*`, переключение через `isFetchrRedesignEnabled()` (по умолчанию redesign). Легаси — это ~10-15k строк мёртвого кода: каждая правка типов/stores проверяется против обоих UI, бьётся i18n и поведение.
Фикс: redesign уже дефолт — удалить `src/features/**/legacy-*`, обёртки-переключатели и сам флаг. Это самое крупное упрощение проекта.

### 3.2 Дублированные утилиты в Rust
- `format_bytes` — 4 копии (queue.rs, fetchr_mute.rs, vocal_remover.rs, copyright_detector);
- `format_duration` — 7 копий (chat_overlay ×5, runner.rs, fetchr_mute.rs);
- `safe_path_part`/`sanitize`/`sanitize_file_stem` — 5 копий с чуть разной логикой (риск: одинаковое имя файла очищается по-разному в разных модулях);
- `emit_log`/`emit` — 3 копии.
Фикс: модуль `src-tauri/src/util.rs`.

### 3.3 Зеркальные пары обработчиков blacklist/whitelist
`FetchrMutePage.tsx:402-580` — `addWordToBlacklist`/`removeWordFromBlacklist`, `handleAdd/RemoveCustomWord`, `handleAdd/RemoveWhitelistWord`, `…KeyDown/Blur` — ~150 строк почти идентичного кода, нормализация слова (`toLowerCase().replace(/[^a-zа-яё0-9]/g,"")`) повторена 8 раз с вариациями.
Фикс: хук `useWordList(kind: "blacklist"|"whitelist")` + одна функция `normalizeWord`.

### 3.4 Гигантские компоненты
`FetchrMutePage.tsx` 1451 строк, `add-dialog.tsx` 1398 (легаси), `LiveRecorderPage.tsx` 1182, `ChatRenderPage.tsx` 784. Внутри смешаны: настройки, плеер, история, транскрипт, dnd.
Фикс: выделить `useMutePlayer`, `MuteHistoryPanel`, `TranscriptPanel`, `WordListsEditor`.

### 3.5 Два источника правды для дефолтного списка слов
Дефолтные маты захардкожены строкой в компоненте (`FetchrMutePage.tsx:48`) и параллельно существует `wordlist.txt` (ресурс бандла). Расходятся молча. Плюс пользователь при первом открытии видит в поле сырой список мата — спорное первое впечатление; лучше показывать «Базовый словарь: 1500 слов (встроен)» и поле только для добавлений.

### 3.6 Чтение настроек страницы мимо общего механизма
`FetchrMutePage.tsx:22-58` — ручной `localStorage.getItem` + 8 useState, хотя есть `usePersistedState` и zustand-persist (`stores/settings.ts`). Три разных паттерна персиста в одном проекте.

### 3.7 Hардкод ключа AcoustID
`modules/copyright_detector/mod.rs:463` — `("client", "cSpUJKpD")` зашит в код. Вынести в конфиг/константу верхнего уровня с комментарием, чьи это креды и какой лимит.

## 4. UX и продукт

### 4.1 Отправка пользовательских слов на сервер без согласия
`suggestMuteWords` (`FetchrMutePage.tsx:390`) тихо отправляет добавленные пользователем слова + machine_id на VPS. Для доверия нужен явный opt-in или хотя бы строка в настройках «Помогать улучшать словарь (отправлять добавленные слова)» — по умолчанию видимая.

### 4.2 Прогресс реального этапа vs «процент задачи»
Жёсткая шкала (скачивание = 0-50/60/70%) делает прогресс нелинейным: короткое скачивание + длинный mute «висит» на 70% большую часть времени. Рассмотреть отдельные индикаторы стадий в строке задачи (download → chat → mute → split) — стадии уже есть в `JobProgress`.

### 4.3 window.confirm для удаления пресетов
`ChatRenderPage.tsx:597`, `M3U8FinderPage.tsx:490`, `SponsorBlurPage.tsx:370` — нативный confirm выбивается из тёмного дизайна, а в WRY ведёт себя по-разному на платформах. В проекте уже есть `tauri-plugin-dialog` и свой Dialog-компонент — использовать их единообразно.

### 4.4 Несогласованные подтверждения
Подтверждение закрытия при активных задачах есть (`lib.rs:130-148`) — хорошо, но текст только на русском и не упоминает live-запись (наиболее болезненная потеря). Добавить в условие активные live-записи и в текст — что именно прервётся.

### 4.5 Мелочи интерфейса
- Кнопка «Запустить всё» в шапке без disabled-состояния при пустой очереди (`title-bar.tsx:106`, проверить TopAppBar).
- Точка-индикатор «новости» горит всегда (`title-bar.tsx:118` — статичный span, не привязан к непрочитанным).
- `purevoice.drag_error` и др. — тексты ошибок только в коде; при выносе в i18n проверить тон и единый стиль («Не удалось…», без «!!»).
- Названия фич в UI: «Fetchr Mute», «PureVoice» (ключи purevoice.*), «Очистка от матов» — три имени одной функции; выбрать одно.

## 5. Гигиена репозитория

В корне проекта (вне git, но мешают навигации и попадают в бэкапы):
- `с.exe` (кириллическая «с») — случайный дубль установщика, 91 МБ;
- `Fetchr-Setup-v0.3.1.exe`, `ffmpeg/ffplay/ffprobe.exe` (~600 МБ), `yt-dlp.exe`, `N_m3u8DL-RE.exe` — вынести в `bin/` или `src-tauri/binaries/`, которые уже в .gitignore;
- `out.mov` (185 байт, битый артефакт), `acoustid_debug.log`, `vite-dev.out.log`, `tsconfig.tsbuildinfo`, `Logs/` — удалить; убедиться, что debug-лог AcoustID не пишется в релизе;
- `ffplay.exe` (200 МБ) не входит в bundle resources (`tauri.conf.json`) — если используется только для дев-просмотра, держать вне корня;
- `README.md` пустой (2 байта) — добавить минимум: что за проект, как собрать (`Build.bat`), структура.

`dist/` закоммичена? — в .gitignore есть, но папка присутствует локально: ок.

## 6. Что уже хорошо

- Продуманная маршрутизация загрузчиков (yt-dlp / N_m3u8DL-RE / ffmpeg-fallback) с понятными логами причин фоллбеков (`runner.rs:219-271`).
- Unit-тесты в критичных местах (fetchr_mute: корни, тайминги, фильтры; twitch-парсеры).
- Нет `unwrap()` вне статических регексов и тестов; `parking_lot`, аккуратная отмена через `AtomicBool`.
- `usePersistedState` корректно обрабатывает переполненный storage.
- Подтверждение выхода при активных задачах, очистка temp при выходе (`perform_cleanup`).
- Эмпти-стейты в очереди с подсказкой действия (`TaskTable.tsx:44-47`).
